Developer guide · Architecture & usage

From raw PDFs to cited answers, in one object

anthropic-contextual-rag is a production-shaped implementation of Contextual Retrieval: a structure-aware chunker, the contextualizer, hybrid search, reranking, and grounded answering — behind a facade small enough to learn in five minutes and seams deliberate enough to replace any stage. This guide covers how it's built, how to use it, and how to tune it. New to RAG itself? Read Part 1, the course first — it builds every concept from zero; this page assumes them.

01Design philosophy: three seams

The package is organized around a simple bet: you will eventually want to swap something — the LLM provider, a retriever, the PDF parser — and the cost of that swap is decided the day the code is structured, not the day you need it. So the architecture is three deliberate seams, and everything else is plain functions between them:

llm.py

The endpoint seam

The only file that imports the OpenAI SDK. Everything else calls llm.chat / llm.embed / llm.transcribe_image. Swap providers with one env var; fake the whole package in tests by patching two functions.

types.ScoredChunk

The retriever contract

A retriever produces a ranked list of chunk ids and joins the RRF fusion. Add a knowledge graph, SQL, or an API as a third voter — nothing downstream changes.

parsing.ParsedDoc

The parser contract

Any parser returning per-page Markdown plugs into the same ingest_pdf path. The vision parser and Azure Document Intelligence are both just backends behind it.

Two more principles run through everything. Lazy configuration: importing the package never requires a credential — only actually calling an LLM does, and a missing key raises a ConfigError that says exactly what to set. A library that explodes at import time can't be tested, vendored, or partially used. And no infrastructure: the vector store is embedded Chroma (on-disk, no server), BM25 is pure Python (sub-millisecond at thousands-of-chunks scale) — the whole pipeline runs from a bare pip install.

02One document's journey

Two flows share one store. Ingestion runs once per document and does all the expensive work; queries are cheap and fast.

Ingestion — once per document
PDF / Markdown→ parse→ chunk→ contextualize→ embed + store
Query — per question
question→ dense ‖ BM25→ RRF fusion→ rerank→ grounded answer [S#]

Abstract diagrams lie by omission, so let's follow one real document all the way through and look at the actual artifacts each stage produces. Every output below is from examples/offline_demo.py — the shipped demo that runs this exact pipeline with the LLM endpoint faked, so you can reproduce all of it in ten seconds with no API key.

1 · chunkchunker.py
from contextual_rag import chunk_markdown

chunks = chunk_markdown(REPORT, doc_id="nightingale.md")
for c in chunks:
    print(c.chunk_id, "·", c.section)

2 · contextualizecontextual.py — one LLM call per chunk
ctx = contextualize_chunks(REPORT, chunks)
print(ctx[2].context)
This chunk is from 'Project Nightingale — Status Report', in the Budget section. ingestion report: 4 chunks · 1,077 contextualizer tokens · 348 cached
3 · store, then searchstore.py · search.py — blurb indexed, original cited

print(hits[0].score, hits[0].citation, hits[0].section)

That's the whole library in four artifacts: chunks with provenance, a blurb per chunk, a store that indexes blurb+chunk but cites the original, and an answer constrained to numbered sources. Every module below exists to produce one of them. The source tree mirrors the flows — one module per stage, named for what it does:

03Module tour — what each file does, and why

ModuleWhat it doesThe design decision inside
rag.py The ContextualRAG facade: ingest_pdf, ingest_markdown, search, ask, search_trace, doc_ids on a named, persistent collection. A thin veneer — every method delegates to a plain function you can call without the facade. The object is convenience, never a cage.
config.py Merges configure(...) → environment → .env into a Settings object, lazily. Code beats env beats file, and nothing is read until first use — the package imports clean with zero credentials.
llm.py chat (buffered + streaming), embed (batched), transcribe_image — against any OpenAI-compatible endpoint. The single provider seam. Also absorbs provider quirks (e.g. retrying with max_completion_tokens when a model rejects max_tokens) so callers never see them.
chunker.py Cuts Markdown on real structure: headings → paragraphs → sentences → hard cuts only for a single giant sentence. ~512-token targets, sentence-snapped ~64-token overlap, full provenance (doc, pages, heading trail) per chunk. Code fences, display math, and tables are atomic — never split even oversized; a torn formula is worse than a big chunk. And nothing is lost: every character lands in a chunk, which is what excerpt mode depends on.
contextual.py One temperature-0 chat call per chunk using Anthropic's published prompt, document first. Falls back to head-plus-region excerpt mode for documents over CONTEXT_DOC_CAP. The first call of each prefix runs alone to prime the provider's prompt cache; only then does the pool fan out. Blurb hygiene strips “Here is the context:” noise that would otherwise get embedded.
store.py Embedded Chroma: per chunk, the embedding of blurb + chunk, the original text as the document, provenance as metadata. Writes are one atomic per-document upsert — a document's presence means it was fully ingested, which is what makes bulk ingestion resumable.
bm25.py Okapi BM25 in pure Python over the same contextual text. No search server. A full scoring pass is sub-millisecond at this scale; operating Elasticsearch would earn nothing.
search.py Runs dense and BM25, fuses with Reciprocal Rank Fusion, reranks, and records a RetrievalTrace of every intermediate stage. Rank-based fusion because cosine and BM25 scores are incomparable scales; the trace exists because “why didn't my chunk come back?” should be a lookup, not an investigation.
rerank.py Three modes: llm (one RankGPT-style listwise call, default), endpoint (hosted cross-encoder, Cohere/Jina shape), off. Ranks blurb + chunk, never the bare chunk (measured: bare chunks made it worse). Defensive by contract: invalid indices dropped, forgotten candidates re-appended — a flaky reranker can reorder but never lose.
answer.py Grounded generation: numbered sources, inline [S#] citations, refuses when sources don't contain the answer, replies in the question's language. Citations resolve to document + page through the chunk's provenance — every claim checkable, and the blurb never leaks into an answer.
ingest.py The one-call pipelines: parse → chunk → contextualize → store, returning a per-document report (chunk count, context tokens, cached tokens). cached_tokens in every report makes the caching economics verifiable per corpus instead of assumed.
index_cache.py Caches each collection's records and BM25 index so queries never pay a rebuild; invalidated on writes. Cached records are immutable templates — per-query scores are stamped onto copies. The one honest gap (a same-count upsert from another process is undetectable) is documented, not hidden.
parsing/ Optional PDF ingestion: per-page tiered routing — free text-layer extraction for confidently clean prose, a vision LLM (Markdown + LaTeX, figures extracted not labeled) for everything else. Azure Document Intelligence as a config-swap alternative. Routing is per page: one chart on a prose page sends that page to vision, so figures are never silently dropped.

05Configure

The package talks to any OpenAI-compatible endpoint. Configuration merges three sources, earlier ones winning: configure(...) in code, then environment variables, then a .env file in the working directory. 

from contextual_rag import configure

configure(api_key="sk-...")                              # standard OpenAI
configure(base_url="https://gateway.example.com/v1")     # corporate gateway
configure(chat_model="gpt-5.4-mini",
          embed_model="text-embedding-3-large")

06The five-minute tour

The whole API most users ever need:

from contextual_rag import ContextualRAG

rag = ContextualRAG("my-corpus")          # a named, persistent collection

# 1 · Ingest — parse → chunk → contextualize → embed → store
rag.ingest_pdf("report.pdf")                          # needs the [pdf] extra
rag.ingest_markdown(text, doc_id="notes.md")          # or skip parsing entirely

# 2 · Search — hybrid (dense + BM25 + RRF), reranked, best first
hits = rag.search("What drove Q3 margins?", k=8)
for h in hits:
    print(h.score, h.citation, h.section)

# 3 · Ask — grounded answer, constrained to sources, cited inline
ans = rag.ask("What drove Q3 margins?")
print(ans.text)                            # "... margins rose 3pts [S1] ..."
print(ans.sources[0].citation)             # "report.pdf, p.12"

Every ingestion returns a report — the numbers that tell you what the document cost and whether caching worked:

report = rag.ingest_markdown(text, doc_id="doc.md")
# {'doc_id': 'doc.md', 'chunks': 42, 'context_tokens': 61_204,
#  'cached_tokens': 48_130, 'excerpted': False}

On a multi-page document, expect cached_tokens to be a large fraction of context_tokens. If it isn't, something changed the prompt prefix between calls — that's your caching alarm.

07Recipes

Debug a retrieval with the per-stage trace

When an expected chunk doesn't come back, don't guess which stage lost it — look: 

trace = rag.search_trace("my question", k=8)
print(trace.timings)                          # {'dense_ms': 42.1, 'bm25_ms': 0.8, ...}
print([c.chunk_id for c in trace.dense][:5])  # what embeddings thought
print([c.chunk_id for c in trace.bm25][:5])   # what keywords thought
print([c.chunk_id for c in trace.fused][:5])  # after RRF
print([c.chunk_id for c in trace.final])      # what the answer will see
print(trace.final[0].scores)                  # {'dense': .83, 'bm25': 7.1, 'rrf': .03, 'rerank': 1.0}

In both lists → RRF handled it. In neither → an indexing problem (was the document ingested? under which doc_id?). In fused but not final → the reranker demoted it.

Scope a question to one document

rag.search("what does the contract say about termination?", doc_id="contract.pdf")
rag.ask("what does the contract say about termination?", doc_id="contract.pdf")

Both retrievers are scoped — another document's passages cannot leak into the results or the answer's sources.

Multiple corpora, one process

finance = ContextualRAG("finance")
legal   = ContextualRAG("legal", rerank="off")   # per-instance override

Collections are fully isolated: separate Chroma collections, separate caches.

Resume a bulk ingestion

Because each document is written in one atomic upsert, presence means fully-ingested — so resuming is a set difference: 

done = rag.doc_ids()
for path in corpus_dir.glob("*.md"):
    if path.name not in done:
        rag.ingest_markdown(path.read_text(), doc_id=path.name)

Use the pipeline as functions — no facade

Every stage is a plain function when you want to own the store or intercept a step:

from contextual_rag import (chunk_markdown, contextualize_chunks,
                            VectorStore, search, answer_from)

chunks = chunk_markdown(text, doc_id="doc.md")
ctx    = contextualize_chunks(text, chunks)      # one LLM call per chunk
store  = VectorStore("corpus")
store.add(ctx)
final  = search("my question", store=store, rerank_mode="llm")
print(answer_from("my question", final).text)

Azure Document Intelligence instead of the vision parser

PARSER=docintel
DOCINTEL_ENDPOINT=https://<resource>.cognitiveservices.azure.com/
DOCINTEL_KEY=...

Same ingest_pdf(...) call — the backend swap is pure configuration.

08Tuning cost & speed

Where the money and the milliseconds actually go. (For the full economics — worked cost math vs. plain RAG, and a provider-by-provider caching guide covering OpenAI, Azure and Anthropic — see the course's money and caching chapters, or docs/costs.md and docs/caching.md in the repo.)

PhaseCostWhen
ChunkingFree (local)ingestion
Contextualization1 chat call per chunk; document prefix billed once, then cached rateingestion (one-time)
EmbeddingBatched at ingestion (64 chunks/request) + 1 call per queryboth
BM25Free (local, pure Python)query
Rerank (llm)Exactly 1 chat call per query — auto-skipped when the pool already fits in kquery
Answer1 chat callquery

Contextualization dominates, and four knobs control it:

CONTEXT_CONCURRENCY — the cache-vs-clock trade. After the priming call, this many workers fan out. On multi-page documents the default 4 wins on wall-clock and the cache holds (measured: 82% of prompt tokens cached in steady state). On short documents — a handful of quick calls — the burst can outrun the provider's few-second cache-settling window; set 1 to give each entry time to land. Check cached_tokens in the report; it will tell you which regime you're in.

A cheap blurb model. Blurbs are a summarization chore, not reasoning — they don't need your best model. Route them per call: rag.ingest_markdown(text, doc_id="doc.md", context_model="gpt-5.4-mini").

CONTEXT_DOC_CAP — match it to your chat model. Keep it ≈20k tokens under the model's usable input (250k fits the GPT-5 family; ~100k for a 128k-context model). Too high and you get hard API errors mid-ingestion; too low merely routes more documents into excerpt mode — a soft, safe failure.

Rerank mode — precision vs. latency. The llm rerank buys the largest precision jump in the benchmark (Pass@1 66.7% → 91.7%) for one chat call of latency per query. Latency-critical paths can set rerank="off" (contextual hybrid alone still hits 91.7% Pass@5); high-throughput ones can point endpoint mode at a hosted cross-encoder.

Rule of thumb

Ingestion is capital, queries are operating expense. Spend at ingestion — blurbs, good parsing — precisely because it's one-time and cached; keep the per-query path to three cheap calls (embed, rerank, answer) plus two free local scans.

09Testing & extending

The test suite runs entirely offline — the LLM and embeddings are faked at the llm.py seam, so the whole suite runs in seconds with no keys and no network. examples/offline_demo.py uses the same trick to run the full pipeline end to end without a key — a demo that doubles as a smoke test: 

pip install -e ".[dev]"
pytest        # offline — a few seconds
ruff check .  # lint-clean under E, W, F, I, B, UP, SIM

The suite pins down the failure modes that were found the hard way — reranker resilience to garbled indices, collection-name collisions, page-provenance honesty for single-blob parsers — so they stay fixed.

Extending follows the seams from §1:

New provider — usually zero code: set OPENAI_BASE_URL to any OpenAI-compatible gateway. Beyond that, llm.py is the only file to touch. New retriever — produce a ranked list and join the fusion in search.py; downstream stages are contract-blind to where rankings come from. New parser — return a ParsedDoc (per-page Markdown) and every ingestion path works, including provenance. New vector store — implement the small VectorStore surface if you outgrow embedded Chroma.

10Reproduce the numbers

The measured results quoted throughout (and analyzed in depth in the course, §10) come from one script: 

export OPENAI_API_KEY=sk-...
python examples/benchmark.py              # ~4 minutes, well under $1
python examples/benchmark.py --no-rerank  # skip the slowest condition

It builds the 12-document synthetic corpus, ingests it twice (with and without blurbs), runs 36 queries through five retrieval configurations, and prints the Pass@k table, cache statistics, and a qualitative side-by-side answer. No dependencies beyond the package itself.

ConfigurationPass@1Pass@5
Plain chunks — hybrid0.0%2.8%
Contextual — hybrid66.7%91.7%
Contextual — hybrid + LLM rerank91.7%97.2%

The benchmark isn't decorative — two of its findings landed as code (rerankers ranking contextual text; cache-settling guidance for short documents). Keep it that way: if you change the pipeline, re-run it, and let the numbers veto you.
